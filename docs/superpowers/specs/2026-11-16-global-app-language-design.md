# 全局应用语言设置设计

## 意图

在设置页「通用」分组中保留现有主题选择，并将行名改为「应用主题」；其下新增「语言」选择。用户切换语言后，应用提供的界面文案应统一切换并在重启后保留。

## 目标

- 支持「跟随系统、简体中文、繁体中文、英语、日语、韩语、西班牙语」七个选择。
- 首次安装默认跟随系统；未支持的系统语言回退到简体中文。
- 本地化应用内所有由项目提供的用户可见文字：页面、菜单、对话框、提示、校验和错误反馈、无障碍描述、应用名称，以及局域网文件传输网页。
- Android 13 及以上在系统的单应用语言设置中提供同一组语言；旧系统也能保存和恢复用户选择。
- 保留现有主题行为、业务流程和用户数据。语言切换不得清除生成输入、导航位置、收藏或正在进行的局域网传输。

## 非目标

- 不翻译用户输入的条码内容、收藏名称、文件名、聊天文本及其他用户数据。
- 不改译码制名称、协议字段、日志、第三方许可原文或由操作系统提供的权限与文件选择界面。
- 不新增第三方语言或本地化依赖，不重写 UI 架构，也不顺带调整未涉及的布局和业务行为。

## 已知约束

- 应用采用 Jetpack Compose；`MainActivity` 已继承 `AppCompatActivity`，项目已有 AppCompat 1.6.1，`minSdk` 为 26。
- 主界面没有可复用的 Android 字符串资源，中文文案主要写在 Kotlin/Compose 代码中；目前 flavor 资源只覆盖应用名称的中英文。
- 设置页已有主题下拉菜单，可复用同一锚定菜单样式和选择反馈。
- 局域网传输网页由 `core:lan-share` 模块动态生成；为满足全局切换，需要传入当前语言并本地化网页文字及面向浏览器显示的错误消息。语言切换不重启分享服务；之后加载的页面使用新语言，已打开的浏览器页面可刷新后更新。
- 遵守现有分层：资源解析留在 UI/平台边界，Domain 不依赖 Android `R`；跨层错误与提示使用稳定类型或错误码，由 UI 按当前 locale 格式化。
- 仓库没有现成的六种译文；实现需同时撰写并校对全部目标语言资源，而非只做语言选择 UI。

## 方案比较与选择

1. **Android 字符串资源 + AppCompat 应用语言 API（已选）**：把文案放入 `strings.xml` 及各 locale 目录，用 `AppCompatDelegate.setApplicationLocales` 管理选择。利用现有 AppCompat，不升级依赖；借助 locale 配置与 Android 13+ 系统设置集成，并对 API 26–32 配置 AppCompat locale 自动存储。
2. **自建 Compose 语言字典**：用自定义语言状态和字典替换硬编码文案。仍需覆盖全部文案，却要自行实现上下文更新、系统设置同步、复数与格式化，且平台资源组件不共享相同 locale，故不选。
3. **只翻译设置页或逐页上线选择器**：工作量较小，但用户选择语言后其他页面仍显示中文，不满足全局切换目标，故不选。

## 行为与实现决策

- 设置分组名为「通用」，主题行名为「应用主题」，语言行紧跟其后；语言菜单沿用项目现有右侧锚定单选菜单。语言名称使用各自的本地名称，避免用户切换后难以识别选项。
- locale 使用不带国家/地区限制的通用语言标签：简体中文 `zh-Hans`、繁体中文 `zh-Hant`、英语 `en`、日语 `ja`、韩语 `ko`、西班牙语 `es`；由系统按设备地区提供区域格式规则。
- 用 AndroidX 应用语言状态作为 locale 来源；「跟随系统」清空 app-specific locale。API 33+ 与系统应用语言偏好同步；API 26–32 启用 AppCompat 自动存储。
- 根据已声明的资源 locale 生成或维护 `LocaleConfig`，仅列出简体中文、繁体中文、英语、日语、韩语、西班牙语。默认资源 locale 为简体中文。
- 所有 Compose 文案改用 `stringResource`；非 Compose UI/平台消息从当前语言 Context 读取。Domain/Data 返回错误类型或稳定错误码，不返回需要翻译的中文展示字符串。
- 日期、数字、复数和大小单位使用 locale-aware 格式化；条码内容和用户数据保持原样。日文、韩文等当前字体未覆盖的字形使用 Android 系统字体回退，并做字形检查。
- 语言设置变更会触发 AppCompat 配置更新/Activity 重建。利用现有 ViewModel、保存状态和局域网服务所有权维持用户当前任务；不得为应用语言切换停止或重启分享服务。
- 本地化译文由实现阶段撰写，使用统一条码/文件传输术语表，并校对占位符、复数、超长文案与语义；不发送项目文本到外部翻译服务。母语人工审校不作为本轮验收条件。

## 验收标准

1. 设置页在浅色和深色主题中显示「通用」分组、「应用主题」和其下的「语言」；现有主题选择可正常工作。
2. 七个语言选项均能选择、显示当前值、即时更新应用文字，并在应用重启后保持；选择跟随系统后跟随设备 locale。
3. Android 13+ 系统应用语言设置显示相同支持集，系统设置与应用内选择互相同步；API 26–32 也能持久恢复选择。
4. 七种 locale 覆盖所有应用自有页面、弹窗、菜单、提示、无障碍文本、版本应用名及局域网传输网页，没有意外回退成中文的应用文案。
5. 语言切换不丢失输入、收藏、当前导航/编辑状态，不重复启动后台操作，也不打断已运行的局域网传输服务。
6. 对每种 locale 检查关键页的浅色、深色呈现及文本溢出；验证日文、韩文、繁体中文字符与长西班牙语文案。
7. 本地完整门禁通过；完成 API 26–32 与 API 33+ 的 locale 持久化验证，并记录真实可复现证据。

## 留给实现阶段的选择

- 用当前 AGP 生成 `LocaleConfig`，或在生成配置不能涵盖 flavor locale 时提供显式 `locale_config.xml`；不得因此升级 AGP。
- 按页面分批搬迁资源，但在切换功能对用户可见前，必须先完成全部目标语言和所有用户可见字符串，避免发布一个只翻译部分页面的全局切换。
- 合并重复文案时只做必要的资源复用，保留语义、占位符及复数规则清晰；不触碰无关布局或交互。

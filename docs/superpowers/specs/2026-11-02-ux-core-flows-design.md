# 核心流程体验优化设计

## 意图

降低条码生成主流程中的等待不确定性和批量录入错误，同时让历史批次的编辑入口更容易发现。优先覆盖高频的生成、结果准备和历史复用流程。

## 用户目标

- 粘贴多行内容后，在加入草稿前知道有效条数、加入后的总条数和具体格式错误行。
- 生成过程中知道已准备数量和总数；结果仍只在整批完成后显示。
- 在历史页能直接发现“查看”“编辑”“删除”三个动作，不必先猜测长按。

## 范围与约束

- 在批量粘贴对话框内即时显示解析摘要或行号错误；不展示条码正文预览，避免额外暴露用户内容。
- 确认操作仍以原有 CSV/逐行解析器与容量规则为准，失败时不部分追加。
- 结果准备增加确定进度条与“全部准备完成后显示”的说明；保留整批就绪屏障、错误和重试行为。
- 历史卡片增加可见编辑按钮，卡片点击查看、长按编辑和删除语义继续可用。
- 不调整导航、数据模型、条码校验规则、分享/保存行为、主题系统或批量上限。
- 代码继续遵守项目 UI/Presentation/Domain/Data 分层、中文意图注释、测试和本地门禁规则。

## 方案选择

1. 只改文案和状态样式：风险低，但批量导入仍需提交后才能知道错误，历史编辑仍隐藏。
2. 为批量粘贴增加纯预览状态、为历史增加直接编辑按钮，并将准备状态显示为确定进度。采用此方案；它改善可发现性和操作前反馈，保持解析与批量显示语义。

## 验收

- 输入为空时显示中性说明；有效粘贴显示待加入条数和加入后总数；CSV/容量错误显示在输入框下方并包含行号（容量冲突除外）。
- 无效或超容量内容不修改原草稿；有效内容只有用户确认后才追加。
- 条码未整批准备完成时，结果行和工具栏都不可见；状态包含 `已准备数/总数`、确定进度以及整批显示说明。
- 历史卡片可通过有语义标签的可见按钮触发编辑；查看、长按编辑和删除不串触发。
- Light/Dark 模拟器截图可查看实际 UI；完整 `verifyLocal` 门禁通过。截图保存在 `.local-validation/logs/`，不提交。

## 取舍与待后续评估

- 第一轮只展示数量，不展示粘贴内容样例，减少敏感条码正文在页面上的重复暴露。
- OCR、局域网分享引导、收藏搜索和整体视觉改版留作后续独立设计，避免本轮跨越太多流程。

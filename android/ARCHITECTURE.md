# 架构原则

本文说明项目为什么采用当前的模块与分层方式，以及必须长期保持的边界。环境配置和运行命令见[开发与验证](DEVELOPMENT.md)；局域网接口细节见 [LAN Share 协议](core/lan-share/PROTOCOL.md)。

## 设计目标

- **业务不依赖界面和设备框架**：条码规则可独立理解和测试，UI 或 Android 实现变化不应迫使业务规则跟着改变。
- **界面与操作结果分离**：Compose 负责呈现和收集操作；状态层编排业务，数据与网络实现负责副作用。这样视觉调整不会意外改变保存或传输行为。
- **数据只有一个权威来源**：已保存的数据由数据层管理，页面状态只描述当前屏幕，避免页面之间各自维护互相冲突的副本。
- **平台与协议细节可替换**：数据库、条码库、Android API 和 LAN 实现通过接口接入，避免具体实现渗入业务核心。

## 模块边界

依赖只能沿图中箭头流动，不能反向依赖或形成循环：

```text
:app ───────────────> :core:domain
  ├────────────────> :core:data ─────────> :core:domain
  └────────────────> :core:lan-share ────> :core:domain
```

| 模块 | 职责与边界 | 这样划分的原因 |
| --- | --- | --- |
| `:core:domain` | 定义业务数据、规则和接口；不依赖 Android、Compose、存储框架或条码库。 | 保持业务规则可独立测试，避免平台更换影响核心逻辑。 |
| `:core:data` | 实现数据接口，负责本地存储、迁移和平台能力适配；不依赖 UI 或 `:app`。 | 把数据库和设备实现留在边界外，保护业务模型稳定。 |
| `:core:lan-share` | 实现局域网服务、客户端和传输协议；依赖 Domain 接口，不依赖 UI、`:core:data` 或 `:app`。 | 隔离网络生命周期与协议变化，避免它们耦合页面和本地数据库。 |
| `:app` | 组合各模块，负责页面、应用流程、Android 交互与依赖注入。 | 作为唯一装配入口，使各 Core 模块可独立演进。 |

Gradle 插件和库版本由 Version Catalog 管理。UI 与 Presentation 目前都在 `:app` 中；包名划分不等同于 Gradle 模块边界。

## 分层原则

- **Domain** 描述业务规则和能力接口，不保存页面状态，也不处理 Android 生命周期。
- **Data / LAN Share** 实现接口并隔离数据库、网络和平台细节。ZXing 由 Data 中的平台适配器封装；Presentation 通过接口请求编码或解码，UI 不直接依赖 ZXing。更换条码库不应要求迁移用户数据。
- **Presentation** 编排业务流程、维护页面状态并发送一次性事件；不能依赖 Compose/UI。页面退出不能取消必须完成的数据写入。
- **UI** 根据状态绘制页面，并把用户操作交回 Presentation；不直接访问 DAO、文件系统或网络实现。路由连接界面与状态层，页面间传递稳定 ID 或不可变参数。
- **视觉组件** 是可替换的 UI 实现，不持有业务或导航状态。动画集中在 `ui.animation`，玻璃材质集中在 `ui.component.glass`；普通内容卡片保持实色。视觉效果不能改变操作命中区域、焦点或业务状态。
- **依赖注入与系统接线** 放在 `:app`。只有明确需要独立复用时，才把装配职责下沉到 Core 模块。

## 状态与数据

- 持续展示的状态使用 `StateFlow` 等状态容器；状态容器不等于持久化，也不自动保证进程重启后恢复。
- 需要可靠送达的单次操作（如系统请求、下载完成）使用 `Channel`；允许未订阅者错过的广播才使用 `SharedFlow`。
- 页面导航由统一状态管理。进程恢复只保存轻量标识；长期数据进入持久化层，不把位图等大对象放入 Saved State。
- 数据模块是已保存数据的权威来源。正式 ID 在数据事务中生成；收藏标记及其关联在同一事务保持一致。写入顺序、失败恢复和旧数据迁移由数据层负责。
- 临时传输文件与用户数据分开存放，不能进入用户备份；存储位置变化时同步检查清理规则。

## 局域网边界

局域网分享由用户主动开启，App 作为创建端，浏览器作为加入端。服务只使用当前 Wi-Fi 地址；同一 Wi-Fi 代表网络可达，不代表身份可信。认证、加密、端口和文件访问范围以[协议安全模型](core/lan-share/PROTOCOL.md#安全模型)为准，界面说明必须与实现一致。离开文件传输页时关闭服务并清理会话文件；进程被强制结束时，清理不保证及时完成，因此后续会话须处理遗留临时文件。

## 如何保持架构一致

- 自动测试覆盖业务规则、数据行为、协议和模块依赖方向。
- Wi-Fi、Android 生命周期、系统选择器和视觉效果须按[开发与验证指南](DEVELOPMENT.md)在设备上检查；编译或单元测试不能替代真机验收。
- 模块、依赖、状态或安全边界变化时更新本文；通信接口变化时更新 [LAN Share 协议](core/lan-share/PROTOCOL.md)；开发命令变化时更新[开发与验证](DEVELOPMENT.md)。

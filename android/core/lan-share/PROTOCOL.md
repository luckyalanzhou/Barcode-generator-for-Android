# LAN Share 通信协议

[项目入口](../../../README.md) · [贡献指南](../../../CONTRIBUTING.md) · [架构原则](../../ARCHITECTURE.md) · 当前：通信协议

> 本文定义 App、浏览器和服务端如何建立连接、交换消息与传输文件。接口变化时，同步更新本文和相关测试。

## 连接方式

- Android App 启动 HTTP/WebSocket 服务；加入端用浏览器打开根页面，不需要安装 App。
- 地址使用当前 Wi-Fi 子网 IPv4 和随机端口 `18080–28080`。新会话会避免紧接着复用上次的端口；端口不是访问凭据。
- App 会检查手动输入或扫码得到的地址是否属于当前 Wi-Fi 子网，不使用 VPN、蜂窝或公网地址。
- 离开文件传输页时关闭服务并清理本次分享文件；进入后台不主动关闭。进程被强制结束时，临时文件可能无法立即清理。

## 安全模型

- 每次主机启动分享服务都会生成新的 256 位随机令牌和 8 位配对码；停止服务后令牌失效。旧版不带令牌的 App 请求会被拒绝，需更新后扫码或粘贴新版完整连接地址。
- Android App 用 `Authorization: Bearer` 访问受保护接口。浏览器扫码地址含令牌；手动输入 IP/端口时，页面要求输入主机显示的配对码，通过 `POST /api/pair` 的 `X-Lan-Pairing-Code` 请求头换取令牌。错误配对按来源 IP 限制为每分钟 5 次。
- `/api/files`、上传、预览、下载和 `/ws` 均必须提供有效令牌。普通网页根路径只返回配对界面，不能读取或操作文件。WebSocket 受浏览器限制不能设置自定义请求头，因此令牌放在握手查询参数中；文件图片和下载链接也用查询参数传令牌。服务端业务日志不记录完整查询串、令牌或配对码，页面设置 `no-referrer` 并在读取令牌后清除地址栏参数。
- 令牌只负责访问授权，不加密流量。HTTP/WebSocket 内容在网络中仍是明文，且同 Wi-Fi 不代表设备可信；界面须提示只在可信网络使用。服务端仍须校验文件名、请求和会话文件范围，防止路径穿越及访问其他文件。

## HTTP 接口

- **`GET /`**：公开返回浏览器配对界面，不返回文件数据。
- **`POST /api/pair`**：通过 `X-Lan-Pairing-Code` 请求头提交主机显示的配对码；成功返回当前会话令牌，响应不可缓存。
- **`GET /api/files`**：需要令牌；返回文件列表，JSON 项包含 `id`、`name`、`size`、`modifiedAt`、`sender` 和 `mimeType`。
- **`PUT /upload?name=...&client=...&transfer=...`**：需要令牌；`transfer` 可选。服务端按原始字节保存，不压缩图片或转换内容，成功时返回文件 ID。
- **`GET /dl/{id}`**：需要令牌；下载会话中的原文件字节。预览不会改写原件。
- **`GET /api/preview/{id}`**：需要令牌；按需生成浏览器可显示的图片。不支持时返回 `406`，原文件仍可下载。

上传时用 `Content-Type` 声明文件类型。固定长度请求使用 `Content-Length` 或 `X-File-Size`；浏览器采用 chunked body 时必须提供 `X-File-Size`。服务端流式写入临时文件，确认实际大小与声明一致后才发布，不会把整个文件载入内存。文件名会清理并限制长度；单文件上限 `10 GiB`，单房间累计上限 `100 GiB`。

文件列表和下载响应保留原始文件名及 MIME 类型。服务只允许访问分享目录中的完整文件，拒绝临时上传文件、路径穿越和不存在的文件。预览缓存与原文件分开保存。

服务最多同时接收 4 个上传，并预留正在传输的容量与 16MiB 存储余量。忙碌或空间不足返回 `503` 和原因，重试须重新发送完整文件；失败和断开释放名额、清理临时文件。容量检查不能代替最终写入错误处理。

## WebSocket 消息

浏览器连接 `ws://{host}:{port}/ws?client={clientId}&token={sessionToken}`；缺少或无效令牌时拒绝握手。连接后发送文本帧 `sync` 获取快照；断线后浏览器每秒尝试重连。非浏览器客户端可用 `Authorization: Bearer` 令牌验证。

快照示例：

```json
{
  "type": "snapshot",
  "files": [
    {
      "id": "...",
      "name": "...",
      "size": 123,
      "modifiedAt": 0,
      "sender": "...",
      "mimeType": "..."
    }
  ],
  "messages": [
    {
      "id": "...",
      "text": "...",
      "sender": "...",
      "createdAt": 0
    }
  ]
}
```

服务端事件：

- **`snapshot`**：`files` 和 `messages`，表示当前文件与文字消息。
- **`message`**：`message`，表示新文字消息。
- **`files`**：`file` 和可选的 `transferId`；后者对应浏览器上传进度。
- **`error`**：`message`，表示可显示的错误信息。

浏览器发送文字：

```json
{"type":"message","text":"你好"}
```

空文字或超过 `64 KiB` 的 UTF-8 内容会被拒绝。App 与浏览器的消息只保存在当前进程中，最多 `100` 条；服务关闭后不保留。连接状态由 WebSocket 的连接/断开事件更新；文件状态通过事件通知，不使用定时轮询。重连后客户端按消息 ID 合并快照，避免重复显示。

## 验证范围

单次服务最多接纳 `16` 个 WebSocket 连接。每个设备独立顺序发送，最多排队 `32` 项；单次写入超过 `5` 秒、发送失败或队列溢出时关闭该连接，避免慢设备拖住其他设备。浏览器继续使用现有重连与快照合并机制。

自动测试覆盖配对码兑换与限速、无令牌拒绝、有效令牌访问、原始字节上传、文件下载完整性、WebSocket 握手与会话状态，以及浏览器配对脚本。真实 Wi-Fi、Android 生命周期和浏览器文件选择器仍需设备验证。
